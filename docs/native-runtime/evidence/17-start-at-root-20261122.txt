Date: 2026-11-22   Device: PLE110 (OPPO, Android 16 / kernel 6.6.118)   Page size: 4096
SELinux domain: untrusted_app (uid 10512)   Rootfs: Ubuntu 24.04, glibc 2.39
Task: the "guest start cwd" item of docs/native-runtime/06-sole-plan-t2t1.md §7, plus a
      full re-run of the 31-check matrix after the wider interposition set of evidence/16.

WHAT WAS WRONG (FACT)
  The launcher starts the process in the app's files directory, which is the *parent* of
  the rootfs. getcwd() there is not under the root, so it cannot be mapped to a guest
  path, and programs that save and restore their initial directory warn:
      find: Failed to restore initial working directory:
            /data/data/com.linuxhub.probe/files: No such file or directory
  (the directory exists, but not in the guest namespace the program is told it lives in.)

THE FIX
  A fourth step in nr_boot: one raw chdir to the root, before any program code runs.
  Guarded: if the inherited /proc/self/cwd is already inside the root, nothing happens,
  because then it is a *meaningful* guest directory (see the regression below).
  Diagnostics no longer echo "nr-init|..." to the program's stderr unless NR_DEBUG is on;
  the launcher sets NR_SIGSYS_LOG unconditionally, so the trap log keeps its marker while
  the program's own output stays clean.

THE REGRESSION THE FIRST VERSION CAUSED (FACT, and why the guard exists)
  v1 of the fix chdir'd to the root in *every* process. Children inherit cwd, so
  `cd /etc && ls os-release` became: child boots, is teleported back to /, then looks for
  os-release in / -> empty. 31 checks -> 28 PASS / 3 FAIL (glob, subshell, exec-rel).
  A direct probe showed the two views disagreeing, which is what identified it:
      cwd0=/ real=/
      cd=0
      pwd=/etc                 <- getcwd() reads the kernel's real cwd
      ls=01-functional-matrix.sh acc.sh bin   <- but the child listed /
      cat=<root>/usr/bin/cat: os-release: No such file or directory
  With the "only when outside the root" guard, inherited guest cwd is preserved and the
  parent-directory case is still fixed. Re-run: 31/31.
