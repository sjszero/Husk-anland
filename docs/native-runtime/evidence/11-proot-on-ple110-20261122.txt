## fact: the guest ELF asks for an absolute interpreter path
$ llvm-readelf -l usr/bin/cat | grep INTERP
     [Requesting program interpreter: /lib/ld-linux-aarch64.so.1]
# PRoot translates the execve() pathname but the kernel resolves PT_INTERP against the
# host root, so /lib/ld-linux-aarch64.so.1 must exist on the *host*. It does not on
# Android; LinuxHub 2.0 works around this with its own loader (jniLibs/libproot-loader.so
# + assets/runtime/arm64-v8a/loader).

# Reading:
# - FACT: proot v5.1 as shipped cannot execute guest glibc binaries here
#   (ENOENT then EACCES once /lib exists). Reproduced with 4 temp-dir variants.
# - INFERENCE: the PT_INTERP above is the blocker; PRoot without LinuxHub's loader has
#   no way to satisfy it inside an app uid.
# - UNKNOWN: whether some proot option we did not try (e.g. their own loader path) fixes
#   it; we did not spend more device time on it because it is the route we are replacing.
# - The shim instead resolves the binary itself, notices the dynamic interpreter and
#   re-execs rootfs' ld.so with --library-path, so stock ld.so is enough and no ptrace,
#   no custom loader, and no extra daemon are needed.
