# 253 · V4L2 假 fd 被 dup2/dup3 覆盖后的身份错误与回收缺口

日期：2026-11-26 12:10（CST）。设备：RMX3357 / MT6893 / Mali-G77 / Android 13 /
kernel 4.19.191 / 4 KiB。探针：`runtime/crates/fd-identity-probe`。

## 0 · 修前事实（FACT）

`dup2(oldfd, newfd)` / `dup3(oldfd, newfd, flags)` 会先关闭 `newfd`，再安装 `oldfd`
的文件描述。V4L2 的 `Ctx::dev_of_fd()` 旧实现只要看到 `devs[i].fd == fd` 就直接认定它是相机，
没有向内核复核 `/proc/self/fd/<n>`。同时 path-shim 的 `dup2` / `dup3` 只清理 DRM / Adreno，
没有通知 V4L2 目标号码已被覆盖。

真机负对照（旧 loader，普通文件覆盖假 `/dev/video0`）：

```text
fdidentity|v4l2-dup2-ordinary-over-fake|FAIL|QUERYCAP=Ok("husk") expected=negative after ordinary overwrite
```

FACT：目标 fd 已经指向普通文件，`VIDIOC_QUERYCAP` 仍被错误送进 V4L2 模拟层并伪成功。
这会让程序把任意复用号码误认成相机。

同一轮还暴露了第二个问题：覆盖后旧 memfd 的 live 引用数可以是 0，但 `Ctx::close()`
只把 `Some(1)` 当成最后引用，`Some(0)` 落进“还有别的 dup”分支，导致 camera.sock 不关闭。
探针表现为假服务器等不到 EOF。

netlink 的同轮负对照全部通过：它本来就按 socket inode 查槽位，不按 fd 号码认身份。
因此 netlink 这一项结论是“核过、不是缺陷”，不是修过。

```text
fdidentity|netlink-dup2-ordinary-over-fake|PASS|family_before=Ok(16) family_after=Ok(1)
fdidentity|netlink-dup3-ordinary-over-fake|PASS|family_before=Ok(16) family_after=Ok(1)
fdidentity|netlink-dup2-fake-preserved|PASS|family_after_source_close=Ok(16)
```

## 1 · 修法

1. V4L2 `dev_of_fd()` 不再使用 fd 号码快路。只要存在打开的相机设备，就必须通过
   `/proc/self/fd` 的 `memfd:husk-v4l2-N` 名称向内核复核身份。
2. `Ctx` 新增 `forget_target(fd)`。`dup2` / `dup3` 成功后通知 V4L2：原目标号码对应的设备
   必须重新核对 live memfd 引用；零引用时关闭 socket，仍有 dup 时保留设备但丢掉旧号码快路。
3. `Ctx::close()` 把 `Some(0)` 与 `Some(1)` 都视为“关闭后没有剩余引用”，统一回收
   camera.sock；读取 `/proc/self/fd` 失败时仍保持 fail closed，宁可保留状态也不误拆活连接。
4. V4L2 preload ABI 同步增加 `forget_target`。当前 preload 仍按 evidence 91 的边界持有独立
   Ctx，本版没有恢复共享函数表；ABI 先补齐，避免以后共用 Ctx 时再次漏掉目标覆盖清理。
5. 新增 `fd-identity-probe` 并接入门禁 A，同时覆盖 V4L2、netlink 的覆盖写与正方向复制。

## 2 · 修后真机结果（FACT）

loader SHA256：`3f4189e2eff1e94a1068484916e5088f95b9f21aa27e12c0518f8e31d6abf495`。

```text
fdidentity|v4l2-dup2-ordinary-over-fake|PASS|QUERYCAP=Err(13) expected=negative after ordinary overwrite
fdidentity|v4l2-dup2-ordinary-over-fake-socket|PASS|camera socket reached EOF after overwrite
fdidentity|v4l2-dup3-ordinary-over-fake|PASS|QUERYCAP=Err(13) expected=negative after ordinary overwrite
fdidentity|v4l2-dup3-ordinary-over-fake-socket|PASS|camera socket reached EOF after overwrite
fdidentity|v4l2-dup2-fake-preserved|PASS|QUERYCAP=Ok("husk") after source close
fdidentity|v4l2-dup2-fake-preserved-socket|PASS|camera socket reached EOF at last close
fdidentity|netlink-dup2-ordinary-over-fake|PASS|family_before=Ok(16) family_after=Ok(1)
fdidentity|netlink-dup3-ordinary-over-fake|PASS|family_before=Ok(16) family_after=Ok(1)
fdidentity|netlink-dup2-fake-preserved|PASS|family_after_source_close=Ok(16)
```

`Err(13)` 是 Android app 域对普通文件 ioctl 的实际拒绝；内核普通文件通常返回
`ENOTTY(25)`。两者都证明调用已经离开 V4L2 模拟层，判据不接受 `Ok("husk")`。

## 3 · 边界

- FACT：本轮动态验证的是 Mali-G77 / Android 13 / 4 KiB 设备上的 V4L2 与 netlink fd 身份。
- UNKNOWN：通过 `SCM_RIGHTS` 把假 V4L2 / netlink fd 送到另一进程后的跨进程状态恢复。
- UNKNOWN：多线程同时对同一 fd 做 `dup2` / `dup3` / `close` 的长时压力；本探针验证顺序语义，
  不冒充并发压力通过。
- FACT：netlink 的覆盖写不是本次修复项；现有 inode 身份检查在三个动态方向上都通过。
