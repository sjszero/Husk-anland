# 106 · 装包链路打通：`apt-get install` 在 guest 里真的能装、能跑 postinst

日期：2026-11-23　设备：RMX3357 / Android 13 / kernel 4.19.191 / 4 KiB / `untrusted_app`
（全部命令在 guest 里跑：app uid 10302，无 root、无 chroot、无 ptrace、无虚拟化）

第二条比第一条重得多：`ca-certificates` 的 postinst 是 **shell 脚本**，要靠
`system(3)` → `/bin/sh -c` 跑起来，还要跑 `update.d` 里的钩子。它能通，说明
"维护脚本"这条路通了，不是只把文件摊在磁盘上。

## 之前卡在哪（五个各自独立的缺陷，全部都实测定位）

### 1. 根文件系统没有 `/bin/sh`：usrmerge 链接被解包器吃掉了

`ls -ld /bin /sbin /lib` 在 rootfs 里是**真目录**，不是指向 `usr/*` 的符号链接。
Ubuntu 24.04 base tarball 里它们是链接（`bin -> usr/bin`），但后续层里有包要装
`bin/fusermount`、`sbin/ip`，而 libarchive/bsdtar 与 toybox tar 遇到"路径中间是符号链接"
时会**把链接换成真目录**再写进去。GNU tar 和 dpkg 是穿过去写的，所以上游系统里看不出问题。

后果：`/bin/sh` 不存在 → apt 的 `DPkg::Pre-Install-Pkgs` 钩子
`/bin/sh -c "/usr/sbin/dpkg-preconfigure --apt"` 起不来 → 装任何包都是
`E: Sub-process /usr/sbin/dpkg-preconfigure --apt || true returned an error code (100)`。

修法（两层）：
* `nr-tools` 的 tar 读取器自己实现（`provision::extract_tar`）：目录成员用
  `create_dir_all`，它**跟随**已存在的目录符号链接；符号链接成员先 unlink 再建。
  现在 `--base` 也走它，不再调宿主 `tar`。
* 已经坏掉的镜像用 `tools/guest-config/repair-usrmerge.sh` 修：条目移进 `usr/`，
  同名冲突时保留 `usr/` 的，目录清空后才换成链接，**不删任何文件**。

### 2. dpkg 状态库是假的：apt 认为 libc6 没装

从 tarball 拼出来的 rootfs 没有 dpkg 数据库，apt 于是要把 **libc6 当成新包装一遍**
——那会把本运行时自己打过补丁的 libc.so.6 覆盖掉。之前手工合成的库还有三个毛病：
`gvfs-backends` 有两条不同版本（dpkg 直接拒绝：*multiple non-coinstallable package
instances present*）、大量条目缺 `Maintainer`（几千行警告）、清单文件名把 epoch
丢掉了（`x11-common_1%3a7.7+23ubuntu3` 记成 `7.7+23ubuntu3`，于是 apt 判成
`debianutils : Breaks: x11-common (< 1:7.7+23~) but 7.7+23ubuntu3 is to be installed`）。

`nr-tools rootfs-status`（纯 Rust）按可信度合并三个来源：base 镜像自带的真数据库 >
树里现有的 > `name_version_arch.deb` 清单；同名按 dpkg 版本序取高者、真元数据优先；
再拿 archive 索引把 epoch/架构补回来（实测 126 个版本 + 139 个架构被纠正）；
最后把运行时**改过的包写 hold**（`Status: hold ok installed`，apt-mark 读的就是这个）：

```
$ dpkg -l libc6
hi  libc6:arm64  2.39-0ubuntu8.7  arm64  GNU C Library: Shared libraries
$ nr-tools rootfs-status --root /tmp/rtdev --base ubuntu-base-24.04.4-base-arm64.tar \
    --list bootstrap-packages.txt --list gnome-packages.txt --list vendor-packages.txt \
    --hold libc6 --hold libc-bin --index-suite noble --index-suite noble-updates
index: reconciled 126 version(s) (epoch) and 139 architecture(s)
dpkg status: 1183 packages   duplicates collapsed: 91   missing Maintainer: 0
```

### 3. dpkg 起子进程一律 ENOENT：exec 家族只 interpose 了 `execve`

```
dpkg (subprocess): unable to execute split package reassembly (dpkg-split): No such file or directory
```
而同一路径在 shell 里 `dpkg-split --version` 完全正常。查 dpkg 的动态符号：
它 `UND execlp@GLIBC_2.17 / execvp@GLIBC_2.17 / system@GLIBC_2.17`，**不 import `execv`**。
glibc 的这些包装函数内部走私有 `__execve`（纯 syscall），没有符号可 interpose，
所以子进程拿到的是 `/usr/bin/dpkg-split` 被当成**宿主**路径。

修法：shim 补 `execl`、`execlp`、`system`。`execl*` 的变参表用一个"比任何真实调用都长的
固定参数表"接收（AArch64 上变参调用与固定参数 callee 的寄存器/栈布局完全一致，
列表以 NULL 结尾，越过结尾的值不会被读；超长直接 `E2BIG` 拒绝，不猜）。
`system` 用 `clone(SIGCHLD)` + 翻译后的 `execve("/bin/sh")` + `wait4` 重写。

### 4. tar 改属主/权限全部失败：`fchown`/`fchmod`/`futimens` 没有接管

```
tar: ./control: Cannot change ownership to uid 0, gid 0: Operation not permitted
dpkg-deb: error: tar subprocess returned error exit status 2
```
tar 不对路径调 `chown`/`chmod`，它对**已打开的 fd** 调 `fchown`/`fchmod`/`futimens`
（实测 tar 的 `UND` 里有这三个，没有 `chown`）。补上：`fchown` 走
`fchownat(fd, "", AT_EMPTY_PATH)`；`fchmod`/`futimens` 走 `/proc/self/fd/<n>`
（fd 是我们的，宿主 /proc 指向的就是 guest 根里的真文件，不需要再翻译）。
假 root 下 `fchown` 直接返回 0。

### 5. `link(2)` 少传一个参数：EINVAL 被报成"无法创建备份文件"

```
dpkg: error: error creating new backup file '/var/lib/dpkg/status-old': Invalid argument
```
dpkg 用 `link(status, status-old)` 做备份。shim 的 `link()` 用 `syscall4` 发
`linkat`，可 `linkat` 有**五个**参数（第五个是 flags），x4 里是调用者残留的垃圾，
内核只好回 EINVAL。`linkat()` 那个符号本来是对的（`syscall5` + SELinux 拒绝时退化成复制），
`link()` 复制粘贴时漏了。改成同样的写法。

### 6. apt 的下载方法被"降权"打死

```
E: Method gave invalid 400 URI Failure message: Could not switch group
E: Method http has died unexpectedly!
```
apt 下载前会 `setgroups/setresgid/setresuid` 切到 `_apt`（实测日志里是 65534/42）。
假 root 下这些调用我们返回 0，但 apt 后续仍判定失败。容器里的通行做法是告诉 apt
沙箱用户就是当前用户：`/etc/apt/apt.conf.d/99husk` 写 `APT::Sandbox::User "root";`
（provisioning 现在自动放这一份，见 `tools/guest-config/apt-husk.conf`）。
这是**配置**，不是绕过：没有第二个 uid 可切，硬切只会失败。

## 顺带确认（FACT）

* `NR_FAKE_ROOT` 现在**默认开**（容器里你就是 root），`NR_FAKE_ROOT=0` 才如实回答。
  `id` → `uid=0(root) gid=0(root)`；`CapEff=0000000000000000`（诚实：没有任何 capability）。
* 剩余噪声：`dpkg: warning: files list file for package 'X' missing; assuming package has
  no files currently installed`。合成库里的包没有 `/var/lib/dpkg/info/*.list`，
  dpkg 只能假设"无文件"。不影响装/删，但 `apt-get remove` 不会删文件——**已知限制**，
  写进 `docs/design/server-surface.md`。

## 复跑

```sh
# 状态库（host 侧，纯 Rust）
nr-tools rootfs-status --root <rootfs> --base <ubuntu-base tar> \
  --list bootstrap-packages.txt --list gnome-packages.txt --list vendor-packages.txt \
  --hold libc6 --hold libc-bin --index-suite noble --index-suite noble-updates

# guest 里
apt-get install -y --no-install-recommends tree ca-certificates
```
