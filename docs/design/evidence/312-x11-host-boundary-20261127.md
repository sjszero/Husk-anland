# 312 · X11 宿主边界：运行环境与显示载体分开验收（2026-11-27）

设备：RMX3357 / MT6893 / Mali-G77 MC9 / Android 13 / kernel 4.19.191 / 4 KiB 页
包：`com.linuxhub.husk`
最终树：`files/rootfs-full -> release-tree-final/root`

## 0 · 结论

- **FACT**：Husk 交付的 Linux 运行资产不包含 X server。最终树里没有
  `usr/bin/Xorg`、`usr/lib/xorg/Xorg` 或 `usr/bin/Xvfb`；只有 `usr/bin/Xwayland`
  作为客户端兼容组件存在。
- **FACT**：最终树的 `run/husk` 只有 App bridge socket，App 私有目录中没有
  Husk 自己创建的 `tmp/.X11-unix/X0` socket。
- **FACT**：因此本轮没有把其他应用（包括 `com.linuxhub.myth.husk`）的 X server、
  `/tmp/.X11-unix` 或旧 PRoot 树的 socket 算作 Husk 验证结果。
- **UNVERIFIED**：Husk 独立 APK 从零启动 GNOME/X11 桌面。当前 APK 是 Linux 用户态
  runtime/debug shell 载体，不是完整的 Android X11 显示服务器；桌面需要宿主 App
  提供 X server 与 Surface 呈现层，或后续单独实现 X server 资产。
- **VERIFIED（运行环境部分）**：在同一最终树上，App bridge、相机、麦克风、GPU 默认值、
  Tree Integrity 和 Gate A 均通过，见 evidence 310。

## 1 · 静态检查

```text
$ run-as com.linuxhub.husk sh -c \
    'ls files/rootfs-full/usr/bin/Xvfb \
        files/rootfs-full/usr/bin/Xorg \
        files/rootfs-full/usr/lib/xorg/Xorg 2>&1'
ls: files/rootfs-full/usr/bin/Xvfb: No such file or directory
ls: files/rootfs-full/usr/bin/Xorg: No such file or directory
ls: files/rootfs-full/usr/lib/xorg/Xorg: No such file or directory
```

```text
$ run-as com.linuxhub.husk sh -c \
    'find files/rootfs-full/run -maxdepth 4 -type s -print'
files/rootfs-full/run/husk/audio-in.sock
files/rootfs-full/run/husk/camera.sock
```

`files/rootfs-full/usr/bin/Xwayland` 存在只说明树里带了 Wayland 下的 X11 兼容客户端，
不等于存在可独立启动的 X server。

## 2 · 验收口径

本版把两件事拆开：

| 层 | 本仓库负责 | 本轮结果 |
|---|---|---|
| Linux 用户态运行时 | loader、path-shim、glibc、rootfs 安装、设备 facade、GPU 默认值 | 最终树 Gate A `34/0/1`，A-hw `11/0`，GPU 默认值 `9/0` |
| Android 显示载体 | X server、输入注入、Surface 合成 | 不属于当前发行资产；独立桌面启动 `UNVERIFIED` |

这不是把桌面功能写成已完成，也不是把旧树里的 socket 借来充当 Husk 的自有链路。仓库介绍
应只把 Linux 运行环境作为已交付对象；桌面/2.0 集成另列为宿主侧能力。
