# evidence 118 — 设备节点面：能用的、平台墙、明确的非目标

设备 RMX3357 / Android 13 / kernel 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。
设计：`docs/design/device-nodes.md`。

## 1. 按名字打开都正常（FACT）

```
/dev/zero      head -c 4  ->  00 00 00 00
/dev/urandom   head -c 4  ->  5f 57 62 82
/dev/random    head -c 4  ->  11 6a d0 09
/dev/null      写         -> ok
/dev/shm       ls -ld     -> drwxrwxrwx husk husk10302
/dev/stdout    -> /proc/self/fd/1
/dev/fd/1      -> pipe:[5751142]
mkfifo /tmp/f  -> prw-rw-rw-
```

## 2. 三条平台墙

### 2.1 `/dev` 列不了（不经 loader 也一样）

```
$ run-as com.linuxhub.husk sh -c 'ls /dev'
ls: /dev: Permission denied
$ ls -ld /dev
drwxr-xr-x 25 root root 5320 /dev
$ ls -ld /dev/full
ls: /dev/full: Permission denied
```

目录权限 `o+rx`，SELinux 仍拒 —— 证明不是 shim 过滤。

### 2.2 `/dev/full`

```
$ echo x > /dev/full
/dev/full: Permission denied          # 连节点都摸不到，更谈不上 ENOSPC
```

要造 `ENOSPC` 必须拦 `write(2)`，而 glibc stdio 走内部 `__write_nocancel`，只拦导出符号
会一半成功一半失败。与"零 ptrace、不扩大拦截面"冲突。**判定为不支持**（JUDGMENT，理由在上）。

### 2.3 `/dev/tty`

```
$ ls -l /dev/tty
crw-rw-rw- 1 root root 5, 0
$ echo hi > /dev/tty
/dev/tty: No such device or address    # ENXIO = 没有控制终端
```

节点在、直通成功，缺的是控制终端（需要会话建立方 `setsid` + `TIOCSCTTY`）。

## 3. 结论

- 运行时该提供的设备面（null/zero/random/shm/pts/mali/video/fifo）**已可用**。
- `/dev` 可浏览、`/dev/full`、`/dev/tty` 三项分别属于：平台限制 / 明确非目标 / 终端载体职责。
- 三项都写进设计文档，避免下一轮再被当成"漏做的 bug"重开一遍。
