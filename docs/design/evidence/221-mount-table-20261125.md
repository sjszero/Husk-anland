# 221 · 挂载表：同一个路径在两个进程里指向两个目录

日期：2026-11-25 22:44–22:50（CST）。设备 RMX3357 / Android 13 / 4.19.191 / 4 KiB。

## 0 · 三条结论

| 问题 | 性质 | 现状 |
|---|---|---|
| 挂载表每进程只读一次 → 别的进程刚 mount 的东西看不见 | **静默写错地方** | 已修：默认每次用到都重读，`NR_MNT_REFRESH=0` 可关（+0.5%） |
| 死挂载项会跨会话累积，攒满 8 条后 `mount` 直接 `ENOSPC` | 功能性（挂载彻底不能用） | 已修：`mount` 前清理后备目录已不存在的项，并把结果落盘 |
| 硬链接的 copy 后备不会跟着源文件后续写入刷新（stdio 写入） | 语义缺口（依赖 L2） | 记录，未修 |

## 1 · 同一个路径，两个目录（已修）

复现（一行一条，`sh` 里跑）：

```sh
rm -rf /mnt/q; mkdir -p /mnt/q
mount -t tmpfs none /mnt/q      # mount=0
echo BBB > /mnt/q/f             # 返回 0
touch /mnt/q/g
ls -A /mnt/q                    # 只看到 g
cat /mnt/q/f                    # No such file or directory
```

宿主侧核对（FACT）：

```
rootfs/mnt/q/f                3 字节，22:43     ← bash 的重定向写到了这里
rootfs/run/husk/t7765753856/g 0 字节            ← touch 写到了挂载目录
```

**根因**：挂载表是 `rootfs/run/husk/mounts` 这个**文件**，而 shim 每个进程只在第一次
用到时读一次（`mnt_ensure` 的一个原子状态位）。于是：

- `mount` 是由子进程做的，写进了文件；
- 已经启动的 `bash`（父进程）表里没有这条，自己的重定向落回 rootfs 里的原目录；
- `bash` fork 的 `touch` 是新进程，读到了这条，写进挂载目录；
- `ls` 也是新进程，看的是挂载目录 → 「写进去的字节消失了」。

**修法**：`mnt_ensure()` 默认每次重读文件（`NR_MNT_REFRESH=0` 关掉）。

**代价**（FACT，`find /usr -name '*.so*'`，约 23 万次路径解析，3 次一组 × 2 组）：

```
refresh=0: 944 948 946 / 951 948 948  ms
refresh=1: 951 959 954 / 955 950 949  ms
```

约 **+0.5%**，在噪声内，所以默认打开。要极致性能可以 `NR_MNT_REFRESH=0` 换回旧行为，
但那等于接受「同一个路径在不同进程里指向不同目录」。

修后同一段脚本：`ls -A /mnt/q` → `f g`，`cat /mnt/q/f` → `BBB`。

## 2 · 死挂载项把表撑满（已修）

tmpfs 的后备目录在 rootfs 里（`run/husk/t<tid><seq>`），进程退出不清理；挂载表也是文件。
于是上一次会话的挂载项跟着下一次会话被读进来。实测：手工塞 8 条指向不存在目录的项后

```
mount -t tmpfs none /mnt/live
→ mount: /mnt/live: mount(2) system call failed: No space left on device   (rc=32)
```

`MNT_MAX = 8`，`ENOSPC` 来自我们自己的表满检查——**挂载功能就这么废了**，而
`/proc/mounts` 还会显示 8 个早就不存在的挂载点。

**修法**：`mount()` 之前跑一次 `mnt_purge_dead()`：用**裸 `openat(O_PATH|O_DIRECTORY)`**
（不经过任何钩子，避免 `readlinkat → mnt_ensure → 重读表` 把刚删的项读回来）判断后备目录
是否还在，删掉并 `mnt_save()` 落盘。

修后：8 条死项 → `mount=0`，`/proc/mounts` 里 dead 0 条、live 1 条。

**踩到的坑**（值得记）：第一版只删不落盘，日志显示 `purge in n=8 / purge out n=0`，
但 `mount` 仍报 `ENOSPC`——因为默认开的刷新会在中间的 `mkdirat` 里把文件重读一遍，
8 条又回来了。**清理必须同时写回文件**。

## 3 · 硬链接 copy 后备不跟随 stdio 写入（记录，未修）

`link(2)` 在 app 数据目录被 SELinux 拒绝，shim 的回退是「复制一份」并登记到
`ALIAS_*` 表，源文件 `close()` 时（`alias_refresh`）把内容重刷一遍。实测：

```sh
echo AAA > a; ln a b; echo BBB >> a
cat a   # AAA / BBB
cat b   # AAA        ← 没有 BBB
```

新旧 loader 行为一致（FACT：`libld.so` 与改动前的 `libld-old.so` 输出相同），所以不是
本轮引入的。根因是 `close(2)` 只有程序自己经 PLT 调用才会被我们钩到，而
**glibc 内部的 `fclose → __close_nocancel` 是直接调用**（同一编译单元，没有 GOT 槽）。
这正是 `libc-interpose.md` 里 L2 体内跳板要解决的那一类问题：L2 现在是 0 覆盖，
所以这条只能等 L2，不是 shim 再加几个钩子能补的。

写清楚影响面：程序自己 `write()`+`close()`（tar、dpkg 解包）刷新是生效的；
经 stdio（`fopen/fclose`）写入的不会。因此**不能把「硬链接模拟」当作完全等价**——
这也和 `docs/LIMITATIONS.md` 里「link count 与共享 inode 丢失」的既有说明一致。
