# 365 · 缩略图黑楔子：根因钉死在驱动里，并**用源码修掉**（H57）

日期：2026-11-27 22:45–23:15（CST）。设备 RMX3357 / MT6893 / Mali-G77 MC9 / Android 13 /
2400×1080，应用 `com.linuxhub.myth.husk`，X `:0`，zink 会话。
承接 361（现场几何）、363（机制切两半，两个二进制补丁都没用）。

**结论先行**：楔子是 **PanVK 侧 `vkCmdBlitImage` 的缩放绘制**把第二个三角形画歪造成的；
`mutter/Cogl` 把窗口缩略图缩小时走的就是这条路，所以**只有桌面也开了 GPU 加速才出现**。
修法是 Mesa 共享运行时 `vk_meta` 里的**单三角形 + 精确 scissor**，源码级、驱动通用，
随包驱动因此改为**源码构建**（不再就地改字节）。

## 1 · 判据链：一步一步把范围切死（FACT）

`gl-probe scale-wedge <WxH> <variant>`：源纹理 2400×1080 白底黑网格，缩到目标 FBO 后读回，
16×8 单元统计暗格（`dark_cells`）。目标先清成**红色**，源用**纯绿**时任何黑色区域都只能
来自“被写成 0”或“根本没执行”。

| 判据 | 变体 | 结果 | 排除 |
|---|---|---|---|
| 清屏覆盖 | `clearonly`（清红，不画） | red=56320/56320 | 目标纹理/清屏没问题 |
| 是否被写 | `blit-green`（源纯绿、目标清红） | **黑 10967 / 红 0** | 不是“没画到”，红色被写掉了 |
| 采样还是执行 | `HUSK_DBG_BLIT_CONST=1`（片元输出常量，不采样） | **楔子照样是黑的** | 不是采样/LOD/mip，是**覆盖** |
| 是不是两个三角形 | `HUSK_DBG_DRAW=1`（只画第 1 个三角形） | black=28176 = **正好半幅**，对角线精确 | 第一三角形、视口、scissor 全对 |
| 同上 | `HUSK_DBG_DRAW=2`（只画第 2 个三角形） | 画成一条斜带，不是右上三角 | **第二个三角形被画歪** |
| 同上 | `HUSK_DBG_DRAW=3`（拆成两次 `CmdDraw(3)`） | 楔子仍在 | 不是“一次画 6 个顶点”的批量/编码问题 |

楔子几何（352×160，逐行扫黑区左边界做最小二乘）：

```
apex (215.0, 61.7)，归一化 (0.611, 0.386)
edge1: 过 (351,0) 与 (0,160)  -> 矩形反对角线
edge2: 过 (351,159) 与 apex
```

⇒ 黑区边界是**矩形反对角线**加一条斜线，不是“少画一整个三角形”那种直角形状，
也不是 tile 边界；说明**图元被扭曲**，而不是区域被裁掉。

## 2 · 驱动侧定位（源码 + 现场日志，FACT）

给 `vk_meta` 与 panvk 加临时探针（`HUSK_DBG_BLIT_LOG` / `HUSK_DBG_VB`）后，一次 blit 的实际参数：

```
META_BLIT r=0 dst=(0,0)-(352,160) src_ext=2400x1080 off=(0,0) scale=(0.00284091,0.00625000) filter=1
META_VB   x_scale=0.00390625 y_scale=0.00781250 rect=(0,0)-(352,160)
  v0=(-1.000000, 0.250000)  v1=(-1.000000,-1.000000)  v2=(0.375000, 0.250000)
  v3=( 0.375000,-1.000000)  v4=( 0.375000, 0.250000)  v5=(-1.000000,-1.000000)
```

- `vkCmdBlitImage` **确实**被用到（zink 的 `blit_native` 把它映射过去），源/目标矩形、
  归一化变换都对 ⇒ 公式没错。
- `create_vertex_buffer()` 写的是 **6 个顶点 = 2 个三角形**，`CmdDraw(6)`。
- 目标 348×156 / 352×160 / 696×312 / 1200×540 全中招，**只有 512×256（视口 2 的幂恰好等于目标）不中招**。
- 结论：Mali v9（G77，jm 路径）把**第二条三角形**画歪，目标里那块就永远没被着色；
  该 render pass 不加载旧内容，于是露出 0（黑）。

## 3 · 修法：单三角形 + 精确 scissor（源码，驱动通用）

`src/vulkan/runtime/vk_meta_draw_rects.c`：

- 新增 `create_fullscreen_triangle_buffer()`：写 3 个顶点，覆盖整个 `[-1,1]` 视口
  （`(-1,-1) (3,-1) (-1,3)`），不需要知道目标尺寸；
- `vk_meta_draw_volume()` 把 scissor 设成**目标矩形本身**，再 `CmdDraw(3)`。

理由与边界：
- 单三角形在这条路径上是**精确**的（§1 的 `DRAW=1` 直接证明），scissor 负责把范围收回矩形；
- 这正是 CSF（`PAN_ARCH >= 10`）路径 `cmd_run_fullscreen()` 原本的形态，**不是按 SoC 分支**；
- 改动在 Mesa **共享运行时**，任何 PanVK（v7/v9/v10、kbase/DRM）都走同一条修好的代码，
  原生本来就正常的驱动按等价语义继续工作；
- 同一份补丁文件：`docs/design/patches/fristonerr-blit-single-triangle.patch`。

顺带把 **kbase 的 2 秒热身改成配置项**（`src/panfrost/lib/kmod/kbase_kmod.c`，默认不睡，
`PANVK_KBASE_WARMUP_MS=2000` 可打开）。这样"关热身"不再需要按偏移改字节。

## 6 · 边界与未做（NOT DONE / UNKNOWN）
