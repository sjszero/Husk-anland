# 258 · V4L2 假节点的 `O_CLOEXEC` / `O_NONBLOCK` 与 netlink 控制项

日期：2026-11-26。设备：RMX3357 / MT6893 / Mali-G77 / Android 13 / kernel 4.19.191 /
4 KiB。探针：`runtime/crates/fd-identity-probe`。

## 0 · 修前事实（FACT）

真机通过 Husk 0.0.30 loader 打开 `/dev/video0`，请求
`O_RDWR | O_CLOEXEC | O_NONBLOCK`，返回的假 fd 同时丢掉两个打开标志：

```text
fdidentity|pathshim-v4l2-open-flags|FAIL|fd=7 fdflags=0 fl=131074 expected_cloexec=1 expected_nonblock=1
```

FACT：`FD_CLOEXEC=0`，且 `F_GETFL` 中没有 `O_NONBLOCK`。影响是相机 fd 可泄漏进 `exec`
子进程，非阻塞采集语义也会失效。

## 1 · 修法

1. `v4l2_open()` 接收调用方传入的完整 open flags。
2. 成功取得假 memfd 后调用 `apply_v4l2_open_flags()`：
   - 请求 `O_CLOEXEC` 时设置 `FD_CLOEXEC`；
   - 请求 `O_NONBLOCK` 时设置 `F_SETFL` 的 `O_NONBLOCK` 位。
3. 任一标志设置失败就清掉 V4L2 身份、关闭 fd，并把真实 errno 返回给 guest。
4. `fd-identity-probe` 新增 V4L2 两项标志断言并接入门禁 A。
5. 新增 netlink `SOCK_CLOEXEC | SOCK_NONBLOCK` 控制断言，确认它不是同类缺陷。

## 2 · 修后真机结果（FACT）

```text
fdidentity|pathshim-v4l2-open-flags|PASS|fd=7 fdflags=1 fl=133122 expected_cloexec=1 expected_nonblock=1
fdidentity|pathshim-netlink-socket-flags|PASS|fd=4 fdflags=1 fl=2050 expected_cloexec=1 expected_nonblock=1
```

`fd-identity-probe` 当前 17/17 条断言通过。netlink 只新增回归断言，没有对应代码改动。

## 3 · 边界

- FACT：动态验证范围是 RMX3357 / MT6893、Mali-G77、Android 13 / 4 KiB。
- FACT：V4L2 修复进入发布包里的 `libld.so`；独立 `libv4l2_preload.so` 不在发布 tar 中。
- UNVERIFIED：V4L2 标志设置失败分支没有在真实设备上人为注入故障。
- UNKNOWN：真实 Camera2 后端在高 fd、长时间 STREAMON、多线程压力下的表现。
- UNKNOWN：跨进程 `SCM_RIGHTS` 传递假 V4L2/netlink fd 后的完整模拟状态。
