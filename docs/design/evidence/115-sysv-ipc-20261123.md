# evidence 115 — SysV IPC（shm / sem / msg）在 guest 里可用

设备 RMX3357 / Android 13 / kernel 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。
脚本：`tools/device-tests/07-sysv-shm.py`（13 项）、`08-sysv-sem-msg.py`（24 项）。

## 1. 起点（FACT）

```
shmget(IPC_PRIVATE,4096,0600|CREAT)          -> -1 errno=38 ENOSYS
semget(IPC_PRIVATE,1,0600|CREAT)             -> -1 errno=38 ENOSYS
msgget(IPC_PRIVATE,0600|CREAT)               -> -1 errno=38 ENOSYS
--- /proc/sysvipc --- False
--- /dev/shm --- True        （POSIX shm 走 /dev/shm，本来就能用）
```

旧文档结论是"不可解除"。复核后判定为**错**：这些是 libc 函数入口，可以接管，和 mqueue 同一类。

## 2. 实现形状

文件 + mmap + flock，细则见 `docs/design/ipc.md` §6。三条要点：

* `shmat` = `mmap(MAP_SHARED)` 段文件，页是真共享；
* `IPC_RMID` = 标记 + 最后一个挂接者离开时删（宽限期）；
* `semop` 在值文件上 `flock`，读全组→判断→全应用，保证跨进程 all-or-nothing。

接管清单新增 8 个符号：`shmget shmat shmdt shmctl semget semctl semop semtimedop msgget msgsnd msgrcv msgctl`
（`BODY_PATCH` 79 → 87；`libc-interpose.txt` 99 项，**94 patched**，跳过的仍是那 5 个老名字）。

## 3. 上机踩到的两个真 bug

1. **死段残留 key 行**：`IPC_RMID` 删了段文件但没删 `keys` 行 → 下次 `shmget(key,O_CREAT)` 命中死 id、
   读不到 meta、返回 `ENOENT`：`shmget(key) creates  id=-1 errno=2`。改成删段即删 key 行 + 读到死 id
   先清行再创建。
2. **`semid_ds` 字段位置**：先上机 dump：

   ```
   0 0 | 8 0 | 16 1649267441664 | 24 0 | 32 0 | 40 0 | 48 0 | 56 0 | 64 4 | ...
   ```

   `sem_nsems` 在 **64**，不是我按教科书猜的 88。且 `IPC_STAT` 只能写这 72 字节：多写 16 字节把
   调用方堆写坏，崩溃点在后面的 `free`（`sig=11 pc=5257432`），排查花了两个来回。
