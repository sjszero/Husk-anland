# 129 · 2.0 换 proot 的实测：环境重置契约、用户身份、以及 su 的缺口

日期：2026-11-23　设备：RMX3357（`UKHMMB8PYTGECMNV`），`run-as com.linuxhub.husk`，rootfs `files/rootfs-full`
被测物：`tools/loader/ld-embedded.so`（`NR_FAKE_UID/GID` + `getgroups`，设备上为 `files/libld6.so`）

## 1. 第一个坑：`env -i` 会把 shim 一起清掉

2.0 的会话是 `… /usr/bin/env -i HOME=… PATH=… <cmd>`。用同样的形状跑：

```
$ ./libld6.so --library-path … usr/bin/env -i HOME=/root USER=root PATH=… /bin/sh -c 'id -u; id -G'
10302                       ← 真 uid，fake root 没生效
10302 1004 1007 … 50302     ← Android 的 gid 全在
/usr/bin/env: error while loading shared libraries: …
```

原因不是 fake root 坏了，而是 `env -i` 清空了 `NR_ROOTFS`/`NR_LD`：shim 靠 `NR_ROOTFS` 找 guest root，
没有它就整条路径链落到宿主。把这两个变量加进 `env -i` 的参数表之后立刻正常（见 §2）。
**结论：换 proot 时，`NR_ROOTFS`/`NR_LD` 必须穿过每一次环境重置。**

## 2. 用户身份（新增能力）

以前 fake root 恒等于 0：`id -un` 永远是 root，想拿用户会话只能照抄 proot 的 `su`。
现在身份跟着 `setuid` 系调用走，并可由环境种入：

| 检查 | 结果（FACT） |
|---|---|
| 默认（不设 `NR_FAKE_*`） | `id -u`=0，`id -un`=root（无回归） |
| `NR_FAKE_UID=1000 NR_FAKE_GID=1000` | `uid=1000(hu1) gid=1000(hu1) groups=1000(hu1)`，`id -un`=hu1 |
| 登录主目录 | `HOME=/home/hu1`，`cd ~` → `/home/hu1` |
| `os.setuid(1001)` 之后 | `getuid()`=1001、`geteuid()`=1001（`getresuid` 也跟随） |
| 组视图 | `id -G` → `1000` 一个（Android 那串 gid 不再出现） |

组视图这条直接删掉了 2.0 的 `ensureAndroidGroupNamesScript`：以前要把 `/proc/self/status`
的 Groups 写进 `/etc/group`（`android_gid_N`）才能压住 "cannot find name for group ID" 噪音。
现在是 `getgroups` 在 fake 身份下只报主组，**从源头没有了**。

## 4. `su` 不能用（UNKNOWN，待定位）

```
$ su --help                 → 正常（Usage: …）
$ su -c 'echo x'            → su: System error   rc=1
$ su hu1 -c 'id -un'        → su: System error   rc=1
$ su - hu1 -c 'id -un'      → su: System error   rc=1
```

- `System error` 是 libpam 的 `PAM_SYSTEM_ERR`：在 `libpam.so.0` 里 `strings | grep "System error"` 命中。
- 把 `/etc/pam.d/su` 换成只有 `pam_permit.so` 的最小配置，**结果不变** ⇒ 与 pam_unix / NSS 无关。
- NSS、locale、fopen、dlopen 都正常（§3）⇒ 不是"libc 内部路径没被 interpose"这个已知缺口的表现。
- `strace` 在设备上不可用：被测进程直接挂住（app 域 ptrace 受限），`timeout` 也杀不掉，只能 `pkill`。

⇒ 目前只能确定"PAM 初始化阶段失败"，**具体点没定位**，按 UNKNOWN 记。
swap 的做法是绕开：会话直接以目标用户身份启动（§2），不经过 `su`。

附：排查过程中一度把设备的 `/etc/pam.d/su` 换成了最小配置（`cp` 到宿主 `/tmp` 失败导致备份没成），
已从 `assets/rootfs/ubuntu-base-24.04.4-base-arm64.tar` 取出原件写回，**大小 2259 字节、61 行**，与改动前一致。
