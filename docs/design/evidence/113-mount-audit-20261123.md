# evidence 113 — 挂载与路径层：外部审计 8 项的复核、修复与实测

设备 RMX3357 / Android 13 / 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。
回归脚本：`tools/device-tests/05-mount-audit.sh`（11 项，全通过）。

## 1. 背景

一份外部审计（针对 `f5bec78`）列了 8 项：4 项"代码逻辑明确"，4 项"高风险待复现"。
**逐条对源码复核，8 项全部成立**，其中 B-01 比报告说的更宽（`pathop` 的 mkdir/unlink/rmdir/symlink
在相对路径下同样绕过只读，因为 `path_is_ro()` 只接受以 `/` 开头的字符串）。本节记录改了什么、
怎么验的。

## 2. 逐项：问题 → 改法 → 实测

| 项 | 结论 | 改动 | 实测 |
|---|---|---|---|
| B-01 只读挂载可被相对路径/目录描述符绕过 | 成立（范围更大） | `openat` 的目录描述符分支加 `ro_gp()`；`pathop`/`pathop2` 改为对解析后的 guest 路径判定；新增 `mnt_unmap()` 把源侧路径反查回挂载点 | 见 §3.1：绝对路径、`openat(dfd,…)`、`mkdir(dfd)`、`unlink(dfd)`、`rename` 全部 `EROFS` |
| B-02 卸载后 tmpfs 存储目录残留，新 tmpfs 可能继承旧文件 | 成立 | 存储目录改成 `/run/husk/t<tid><seq>`（不再用表索引，索引会被复用）；`umount2` 在锁外递归删除该目录 | §3.2：旧文件不见了，存储目录也不残留 |
| B-03 挂载表序列化缓冲区 2048 字节，最坏 2080 字节，静默截断 | 成立 | 缓冲区 4096；`mnt_pad` 改为失败即返回，写半行改为整条丢弃 | §3.3：8 条 127 字节目标 + 127 字节源 = **2080 字节**，8 条全部可解析 |
| B-04 等长映射导致链式挂载提前停止 | 成立 | `mnt_apply` 返回 `Option<usize>`，"没匹配"与"长度没变"分开 | §3.4：等长两跳链读到最终内容 |
| B-05 `cwd()` 返回指向全局缓冲区的切片，多线程竞争 | 成立 | 删除 `CWD_BUF/CWD_LEN/CWD_STATE`，改 `cwd_into(&mut buf)` 每调用自带缓冲 | §3.5：6 线程 × 12000 次解析 + 挂载抖动，0 错误 |
| B-06 挂载表无同步；`MNT_READY` 在读之前就置位 | 成立 | 一把只保护表的自旋锁（写者在"改+落盘"期间持有）；加载改为 `0/1/2` 状态机 + 记录加载线程 tid（自线程重入直接返回，不自杀）；`/proc/mounts` 生成也持锁 | 同上；`/proc/self/mounts` 条目与实际表一致 |
| B-07 xattr 走 `/proc/self/fd/<父>/<名>`，末段名字仍会被内核重新解析 | 成立 | 新增 `xattr_pinned()`：先 `target_fd()` 固定 inode，再把 `/proc/self/fd/N` 交给内核（`l*xattr` 保持原样——内核不跟随末段，无越界面） | §3.6：`set/get/remove` 正常 |
| B-08 `linkat` 手解析旧路径后仍传 `AT_SYMLINK_FOLLOW` | 成立 | 跟随语义下先钉住旧对象，`linkat` 只拿到 `/proc/self/fd/N` | §3.7：`ln -L` 成功（本域 `link(2)` 被拒，仍走拷贝回退） |

顺带修正一处：`mnt_save()` 原先在表未满时也可能因为打开失败而**静默不落盘**；现在它用的
`mnt_open_table()` 不查表（避免持锁时重入），失败仍静默但只在目标目录不可建时发生。

## 4. 仍然存在、并且刻意没有"修"的

1. **同进程可见性**：表在进程首次解析路径时加载一次，之后不重读。所以"shell 里 mount、同一条 shell
   里重定向写入"这条路径看不到新挂载（子进程能看到）。这是设计取舍，不是这次的 bug；真要修，
   需要每次解析都 stat 一次表文件，代价与收益不成比例。
2. **util-linux 的 `mount -o remount,ro,bind <target>`** 会先查 `/proc/self/mountinfo` 再决定，
   目前报 `mount point not mounted or bad option`（rc=32）。单次调用形式 `mount -o bind,ro` 正常。
   合成的 mountinfo 字段还不够像真的（缺少 optfields / 真实 major:minor 与源设备），列在 B 段待办。
3. **只读判定仍不覆盖** `chmod/chown/utimensat`（已知限制，未变）。
4. 最多 8 个挂载点、单条路径 <128 字节（未变）。
