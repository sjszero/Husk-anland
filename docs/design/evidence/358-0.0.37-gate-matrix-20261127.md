## 8 · 干净目录安装（H45）：一条只在空目录上出现的 libc 找不到

`--fresh` 装到空目录时，pass 2 立刻失败：

```
== pass 2: re-extract through the shim (fixes hard links) ==
   usr/bin/env: error while loading shared libraries: libc.so.6: cannot open shared object file
install-husk: pass 2 failed (tar rc=127); hard links are not materialised, this tree is broken
```

可复现（RC=69，两次）。根因不是 tarball 坏了：安装器在**任何解包之前**就按“目录此刻是否存在”
决定库搜索路径：

```sh
LIBS="$DEST/lib/aarch64-linux-gnu:$DEST/usr/lib/aarch64-linux-gnu"
[ -d "$DEST/usr/lib/aarch64-linux-gnu" ] || LIBS="$DEST/usr/lib"
```

空目录上 `[ -d ]` 判假 → `LIBS` 塌成 `$DEST/usr/lib`，而 Ubuntu 的 libc 在
`usr/lib/aarch64-linux-gnu/`，于是 pass 2 的 `env` 找不到 libc。升级装因为树已经存在，
从来没暴露过——这也是它从 0.0.30 一路活到现在的原因。

修法：库搜索路径固定列出四项（`lib/aarch64-linux-gnu`、`usr/lib/aarch64-linux-gnu`、
`lib64`、`usr/lib`），不按目录存在与否二选一；缺的目录 loader 自己跳过。

修完之后，用设备上现成的 33 MB 精简 tarball（`husk-base3.tar.gz`，不是完整 Ubuntu 基础包）
做干净装：

```
RC=0   mode=install
version=0.0.37  loader_sha256=67f543b9…  libc_sha256=16d5ba21…  panvk_driver_sha256=f73600da…  icd_sha256=25f6ccd9…
== done ==   usr/bin/bash -l -c 'id; head -1 /etc/os-release'  → 正常输出
TREE_INTEGRITY PASS=12 FAIL=2
ICD_CANONICAL  PASS=12 FAIL=0 SKIP=1
```

两条 TREE_INTEGRITY 失败是**这棵精简树没有 gdk-pixbuf / shared-mime-info 工具**，所以
`usr/share/mime/mime.cache` 与 `gdk-pixbuf loaders.cache` 生成不出来（不是安装器写错）；
`ICD_CANONICAL` 的 1 条 SKIP 是因为发行包不带 `vulkan-probe`，探针那一段只能在有探针的树上跑。

**UNVERIFIED**：设备上没有完整的 Ubuntu 24.04 基础包（4.3 GB），所以“从 stock tarball 干净装
并在完整树上跑门禁 A”这件事这一轮没做。上面能证明的是**安装器在空目录上不再失败**。
