# 186 · 窗口"扭曲/折掉"：不是抓图问题，是 GTK4 的 GL 渲染在 zink/PanVK 上画错

日期：2026-11-25 12:29–12:35（CST）。设备 RMX3357（MT6893 / Mali-G77 MC9 / Android 13 /
4 KiB 页），应用 `com.linuxhub.myth.husk`。触发场景：把 X 屏从 1200x540 抬到 2400x1080 后用
`gnome-calculator` 看界面。用户看到"跟扭曲了一样、出界、深色地方不对"。

## 1 · 先排除抓图

两条完全独立的取像素路径，结论一致：

| 路径 | 命令 | 结果 |
|---|---|---|
| guest 侧读 X root | `gl-probe-new2 root` → `$R/tmp/root.ppm` | 有楔形残缺（见图 1） |
| Android 物理屏 | `adb exec-out screencap -p` | 同一块楔形、同一位置（只多一个鼠标指针） |

FACT：残缺在 X 服务器的 framebuffer 里，不是 `gl-probe` 的读像素 bug，也不是 AHB 上传丢失。

## 2 · 三组对照，把范围压到 GL 路径

同一个二进制、同一条命令行、同一个窗口，只换渲染后端，各起一次并各抓一张：

| GSK_RENDERER | GL 后端 | 结果 | 图 |
|---|---|---|---|
| `ngl` | zink → PanVK（Mali） | 窗口圆角/阴影出现大三角缺口，输入区出现斜向亮带 | `186-gtk4-wedge-ngl-zink.png` |
| `ngl` | llvmpipe | 干净 | `186-gtk4-clean-ngl-llvmpipe.png` |
| `cairo` | 无 GL | 干净 | `186-gtk4-clean-cairo.png` |

推论（INFERENCE）：X 服务器、path-shim 的路径层、mutter 合成都不是嫌疑人——三者在这三种配置里
完全相同，唯一变化的是客户端自己的 GL 绘制。缺口出现在 GTK4 自己画的 CSD 圆角/阴影和输入区
背景上，按钮网格（纯色四边形 + 文字）反而是好的。

## 3 · 确定性

同一配置连抓两帧（间隔 2 s），`cmp` 完全一致：

```
IDENTICAL (deterministic)
```

所以不是撕裂、不是 swap 竞态、不是抓帧早于合成完成；是每条指令都会稳定画错。

## 4 · 没定下来的：zink 还是 PanVK

想做 zink + lavapipe（Vulkan 也走 CPU）来二分，失败：

```
MESA: error: ZINK: failed to choose pdev
MESA-EGL: warning: egl: failed to create dri2 screen
```

`lvp_icd.json` 的 `library_path` 是裸 soname `libvulkan_lvp.so`；改成宿主绝对路径的
`$R/tmp/lvp-abs.json` 后仍然 `failed to choose pdev`。

FACT：这次没能把 lavapipe 拉起来，所以"zink 的锅还是 PanVK 的锅"目前是 UNKNOWN。
形状上（四边形退化成三角形）更像顶点/索引被读错，但也可能只是采样常量的精度问题，不能靠形状定罪。

## 5 · "出界"是另一回事：旧窗口带着 1200x540 时代的几何

| 窗口 | xwininfo 几何 | 说明 |
|---|---|---|
| 旧 Calculator（1200x540 那会儿起的） | `482x614+998+-21` | y=-21，标题栏在屏幕外；y≈(540-614)/2，是按 540 高的屏幕居中的 |
| 新起 Calculator（2400x1080） | `482x614+89+19` | 正常落在屏内 |

FACT：改分辨率没重启会留下错位的旧窗口。0.0.6 要在切模式时重新摆放/重启客户端，
不能指望用户自己关窗。

## 6 · 另外两处"看着不对"，查清了，不全是 bug

- 桌面图标文字显示成"主目""回收"：像素级对比后是**计算器窗口压住了标签**（窗口 x=89 起，
  图标在 x≈100–150），不是文字被裁。换一张没有重叠的抓图（`186-gtk4-clean-cairo.png`）里
  "主目录""回收站"完整。→ 撤回"标签被裁"的假设。
- 深色/配色不对：`org.gnome.desktop.background picture-uri = file:///usr/share/backgrounds/gnome/adwaita-l.jpg`，
  `picture-options = zoom`，`primary-color = #023c88`。那是 GNOME 默认壁纸，不是 Ubuntu 的。
  和 evidence 184 的 GTK 主题问题同源：`ubuntu-settings` 那套默认值整体缺失，只补了 gschema
  override 的 GTK 部分，**背景/壁纸还没补**。

## 8 · 对 0.0.6 的要求

1. "窗口能用"的前提是画对。zink/PanVK 这条 GL 路径在修好之前，GTK4 应用的默认渲染器必须落到
   能画对的路径（`cairo` 或 `ngl`+`llvmpipe`），GPU 加速只作为可选开关，不能默认开。
2. 定位到具体是哪一层：先用能起来的 Vulkan CPU 驱动重做 zink 二分；再按
   "顶点/索引读错"方向查 PanVK 的 vertex fetch 与 GSK 的 shader 组合；Mesa 版本升级也要试。
3. 切分辨率要重建会话几何，不能留下 y=-21 这种窗口。
4. 背景/壁纸默认值纳入 `husk-look.override` 的同一套修法。
