# evidence 121 — 出口流量通了（DNS / TCP / HTTP / HTTPS / apt）

设备 RMX3357 / Android 13 / kernel 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。
设计：`docs/design/network.md` §5。测试：`tools/device-tests/13-egress.sh`（6 项，全通过）。

## 1. 症状（FACT，修之前）

```
$ curl -4 -s -o /dev/null -w '%{http_code}' http://ports.ubuntu.com/.../Release
000                                    # 解析到了 172.66.152.176，但连不上/发不出去

$ curl -4 -v http://ports.ubuntu.com/.../Release
* Connected to ports.ubuntu.com (104.20.28.246) port 80
* Send failure: Invalid argument
* Failed sending HTTP request

$ python3 -c 'connect + s.sendall(req)'   # 同一个 IP、同一个端口
recv: b'HTTP/1.1 200 OK\r\n...'           # 正常
```

同一台机器：`connect()` 成功、Python 的发送成功、`curl` 的发送 `EINVAL`。

## 2. 根因（FACT）

shim 的 `send` interpose 用了 4 参数的 syscall 去调 **6 参数的 `sendto`**：

```rust
ret_or_errno(syscall4(SYS_SENDTO_NR, fd, buf, len, flags))   // x4/x5 未设置
```

`sendto(fd, buf, len, flags, dest_addr, addrlen)` 的第 5 个参数从 `x4` 读。`syscall4`
不写 `x4/x5`，内核就把调用者残留的寄存器值当成 `dest_addr` 指针 → 已连接的 socket 上传了
一个目的地 → `EINVAL`。`curl` 走 libc 的 `send`，命中；Python 的 `sendall` 走的是
`sendto`/`write` 的另一条路，绕过了。

改成 `syscall6(..., 0, 0)` 后立即恢复。

## 5. 教训（写下来免得再犯）

arm64 上少传 syscall 参数**不会**报"参数不足"，`x4/x5` 里的残留值会被内核当真。表现为
一个语义莫名的 errno（这里是 `EINVAL`）。所以：

* 加 syscall 包装时按**内核原型**的参数个数写，宁可多传 0；
* 网络面必须用**真实客户端**（curl / apt / wget）验收，只测 `connect()` 会漏掉一半。
