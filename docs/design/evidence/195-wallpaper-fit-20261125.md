# 195 · 壁纸右上一块"黑了"：缩小采样的贴图在 zink/PanVK 上只画 32% 亮度

日期：2026-11-25 15:05–15:22（CST）。设备 RMX3357（MT6893 / Mali-G77 MC9 / Android 13 /
4.19.191 / 4 KiB 页），应用 `com.linuxhub.myth.husk`，X server `:0`（应用自己的 `:x11`）。
现场：zink 会话（`!MESA_LOADER_DRIVER_OVERRIDE=zink` / `!GALLIUM_DRIVER=zink`），
`gnome-shell` 3.36→46（Ubuntu 24.04），会话进程由 `sess-host.sh` 起。

用户看到的是"右边缺了一块、成黑色了、像一个三角"。这份把它钉死：**是什么形状、差多少、
在什么条件下出现、什么条件下不出现**，并给出已经在设备上验过的绕法。

## 1 · 取像素

`xcap`（evidence 194 §4）直接 `XGetImage(root)`，读的是 X server 的 root window，
不受 `screenrecord`/`screencap` 那些应用层覆盖影响。全部数字都是对 root window 逐像素算的。

## 2 · 形状（FACT）

把屏幕和 `usr/share/backgrounds/warty-final-ubuntu.png`（3840×2160，按 zoom-fill：
scale = max(2400/3840, 1080/2160) = 0.625，纵向居中裁掉 135 行）逐点比，得到比值
`屏幕 / 壁纸`。比值只有两个值：**1.00** 和 **0.32**，没有中间态（直方图：
`[0,0.1)=0，[0.3,0.4)=0.366，[0.9,1.1)=0.487`，其余是窗口和图标）。

0.32 这块区域的边界是两条直线，逐行扫描（每 10 行一个点）拟合出：

| 边 | 方程 | 说明 |
|---|---|---|
| 上臂 | `x = 2223 − 1.3·y` | y=40 时 x=2171，y=170 时 x=2001；出屏在 y=0 处 x≈2223 |
| 下臂 | `x = 643 + 1.3·y` | y=840 时 x=1735，y=1050 时 x=2108；出屏在 y=1080 处 x≈2047 |
| 交点 | ≈ (1433, 608) | 落在终端窗口（x 660–1678、y 240–718）后面，抓不到，由两条臂外推 |

也就是说：**屏幕右侧被切出一个"人字形"楔子**，楔子里是同一幅壁纸，亮度和几何都对，
只是整体被乘了 0.32。窗户外侧、y<420 和 y>840 两段都能直接量到，数字一致。

## 3 · 楔子里的内容是对的，只是暗（FACT）

三组对照，都在同一个 shell 进程里：

**a) 白底 + 200 px 网格的测试壁纸（3840×2160）**

| 位置 | 正确区 | 楔内 |
|---|---|---|
| 竖网格线 | x = 250, 375, 500, 625, … | x = 1875, 2000, 2125, 2250, 2375（同样 125 px 间隔，位置接得上） |
| 横网格线 | y = 31, 115, 240, 365, 490, … | y = 31, 115, 240, 365, 490, …（完全一致） |
| 白底 | 255 | 82 |

格线位置逐条对得上、白底 255→82 ⇒ 不是采样错位、不是缩放比例错，是**乘了一个常数**。

**b) 0..255 水平渐变壁纸（3840×2160）**

| 屏幕 x | 该处应显示 | 楔内实测 | 比值 |
|---|---|---|---|
| 2100 | 223 | 71 | 0.318 |
| 2200 | 234 | 75 | 0.320 |
| 2300 | 244 | 78 | 0.320 |
| 255 峰 | 255 | 82 | 0.322 |

比值在 0.318–0.322，跨亮度不变 ⇒ 确实是"乘以 ~0.32"（82/256 = 0.320），不是 mipmap 平均、
不是 gamma、不是采样到别的区域。

**c) 窗口不受影响**：同一行 y=700，楔子边界 x=1313 两侧，终端窗口底色都是 `56,12,42`。
楔子只吃背景，不吃窗口。

## 4 · 触发条件（FACT，同一个会话里 live 切换，间隔 7 秒）

| 壁纸 | 右侧 y=100 的像素 | 结论 |
|---|---|---|
| `warty-final-ubuntu.png`（3840×2160，要缩小） | 18 / 19 / 19 | 楔形，0.32 |
| `husk-warty-2400.png`（2400×1080，1:1） | 57 / 59 / 60 | 正确（参考值 57/58/59/60） |
| 再切回 3840×2160 | 18 / 19 / 19 | 楔形回来了 |

另一组独立验证（渐变图）：3840×2160 → 右侧 71/75/78；换成 2400×1080 → 全宽
`14,21,42,63,85,106,…,233` 干净到底。

再加一条反证：`picture-uri=''` + `primary-color=#00ff00`（纯色底）时整屏 `(0,255,0)` 全亮，
**没有楔形**。⇒ 不是"背景 actor 没覆盖整屏"，也不是某个 dim 图层，而是**贴图缩放那条路**。

## 5 · 和 llvmpipe 那个缺陷不是一回事（FACT）

`HUSK_GPU=llvmpipe` 起的会话：背景只画 `0..479` 行（全宽，逐列验证 `x=300` 与 `x=2200`
最后一个非黑行都是 479），y≥480 全是 0；换成 1:1 的壁纸也一样。
⇒ llvmpipe 的残缺与壁纸尺寸无关，是另一个口子（另行处理）。

## 6 · 试过但走不通（FACT）

`COGL_DRIVER=gl`（想用桌面 GL 绕开 GLES2 这条）：
`Failed to setup: Unable to initialize the Clutter backend: no available drivers found.`
这个 mutter 只编了 gles2 driver，绕不过去。

## 7 · 根因（UNKNOWN）+ 同族证据（INFERENCE）

楔子是"两层直边、形状固定、内容正确、整体乘常数"，且两种渲染器表现完全不同。
本轮**没有**拿到 driver 级根因，不编。可以确定的只有：

- 触发物是"需要缩小采样的贴图"（比屏幕大的壁纸），不是贴图内容、不是 actor 几何；
- 症状和 evidence 186 是同一族：那条记录里 GTK4 用 `GSK_RENDERER=ngl`（zink→PanVK）
  时，窗口圆角/阴影同样出现**三角缺口**，换 llvmpipe 或 cairo 就干净。
  ⇒ INFERENCE：这是 zink/PanVK 这条路径上"一个四边形被画成缺一块"的家族问题，
  不是 mutter 的 JS、不是 path-shim、不是 X server。

## 8 · 绕法（已在设备上验过，FACT）

既然 1:1 就是对的，就让 mutter 永远不要缩小壁纸：会话起来后把当前壁纸缩成**恰好屏幕尺寸**，
再把 `picture-uri` / `picture-uri-dark` 指过去。

实现（全在运行时层，不动 2.0 代码）：

| 文件 | 作用 |
|---|---|
| `tools/guest/husk-wallpaper-fit.sh` | 宿主侧看护：等 X 和会话总线 → `xdpyinfo` 读 `current WxH` → 读 `picture-uri` → 缩放 → `gsettings set` |
| `tools/guest/husk-wallpaper-scale.js` | guest 侧 gjs：`GdkPixbuf` 按 zoom-fill 缩放 + 居中裁剪，存 PNG |
| `tools/guest/husk-session.sh` | 起 `gnome-shell` 时和 DING 兜底一起 fork 出去 |
| `tools/guest/install-husk.sh` | 把 js 装进 `usr/local/share/linuxhub/` |

实测（15:22）：`picture-uri -> /home/husk/.cache/husk/wallpaper-2400x1080.png (2400x1080)`，
生成 1.48 MB PNG；抓图后右侧 y=100 为 `58/59/61`，与参考 `57/58/59/60` 一致，楔形消失
（`195-wedge-before-after.png` 下半张）。

注意：纯色底不动（`picture-uri` 不是 `file://` 就退出）；失败一律静默，不挡会话。
`apt upgrade` 或应用自己重设 `picture-uri` 之后，下一次会话会重新贴合。

## 9 · 仍未解决

1. 楔子的 driver 级根因（UNKNOWN）。要动它得靠 Mesa/PanVK 侧，或在 mutter 里避开
   mipmap/缩放采样；本轮只做了绕法。
2. llvmpipe 会话"只画 0..479 行"（独立缺陷，与壁纸无关）。
3. 换分辨率后缓存 PNG 会按新尺寸重新生成，但**已经贴在屏幕上的窗口**还是旧几何
   （evidence 186 §5），那是另一条待办。
