## 1 · A3：会话总线拒绝 root 客户端（FACT）

认证是成功的，问题在认证**之后**：

```
$ python3 /tmp/dbus_hello.py linuxhub-session-bus-husk EXTERNAL
auth: b'OK bb0783791e4420f56ecfc8766b052bbc\r\n'
  File "/tmp/dbus_hello.py", line 44, in <module>
    s.sendall(hello_msg())
BrokenPipeError: [Errno 32] Broken pipe

$ python3 /tmp/dbus_hello.py linuxhub-session-bus-husk ANONYMOUS      # 同样的服务器
auth: b'OK bb0783791e4420f56ecfc8766b052bbc\r\n'
hello reply len 260 ...                                              # 匿名反而通了

$ python3 /tmp/dbus_hello.py testbus-abc EXTERNAL                     # 我们自己刚起的总线
auth: b'OK 3d4b70d29502ebf3f9bb40c36b052de9\r\n'
hello reply len 258 ...
```

同一个配置、同一个客户端，唯一差别是**总线属主的 uid**：临时总线由终端进程拉起（也是 0），
会话总线由 uid 1000 的桌面拉起。`dbus-daemon` 对 EXTERNAL 客户端只放行"与属主同 uid"，
其余一律在 BEGIN 之后断开——而会话总线的 `<policy>` 里没有 `<allow user="*"/>`
（系统总线有，所以系统总线一直能用）。补齐后：

```
$ DBUS_SESSION_BUS_ADDRESS=unix:abstract=linuxhub-session-bus-husk \
    dbus-send --session --print-reply --dest=org.freedesktop.DBus / org.freedesktop.DBus.ListNames
method return time=1795502541.697277 sender=org.freedesktop.DBus -> destination=:1.48 serial=3 reply_serial=2
   array [ ... ]

$ gio mount -l          # 修复前是 5 条 "Error creating proxy: The connection is closed"
（无输出，即无错误）
```

> 附带记录：`gio` 还会警告 `Error creating IO channel for /proc/self/mountinfo: Operation not
> permitted`。这与 A3 无关，是另一件事（shim 未接管 mountinfo），暂记为 UNKNOWN 项。

## 2 · A4：RandR 版本与缩放能力不符（FACT）

```
$ DISPLAY=:0 xrandr --version
xrandr program version       1.5.2
Server reports RandR version 1.2          # 修复后（修复前报 1.6）

$ grep -c "Impossible to set scaling" /tmp/doro-gnome-shell.log
0                                          # 修复前每次启动都有一条（crtc 63）
```

机制：mutter 只用版本号推断能力（`meta-monitor-manager-xrandr.c:1235`：

```c
if (xrandr_manager->randr_version >= RANDR_TRANSFORM_MIN_VERSION)   /* 1.3 */
  capabilities |= META_MONITOR_MANAGER_CAPABILITY_NATIVE_OUTPUT_SCALING;
```

然后在 `meta_crtc_xrandr_set_scale()` 里发 `RRSetCrtcTransform`；而本服务器
`RRCrtcCreate(pScreen, NULL)` 没开 transform（`RRCrtcTransformSet` 见 `!crtc->transforms`
直接返回 BadValue）。既然这台 X server 兑现不了 transform，就只报 1.2——这是它真正能守住的
最高版本，mutter 于是走"全局缩放固定 1"的正路，不再尝试。

缩放的可用人路径改由应用侧提供：X 画面尺寸小一档 + 拉伸到屏幕（分辨率模式 = 缩放），
同时 `xrandr` 仍照常列出模式与当前尺寸：

```
$ DISPLAY=:0 xrandr
Screen 0: minimum 1 x 1, current 2400 x 1080, maximum 32767 x 32767
builtin connected primary 2400x1080+0+0 0mm x 0mm
   2400x1080     29.93*
```

## 3 · A5：输入几何为 0，模式 2/3 的点击被整批丢掉（FACT）

代码路径：

- `TouchInputHandler.handleTouchEvent()`：finger + 非 trackpad → `mInputStrategy.onMotionEvent()`
- `GestureListener.onTap()`：非 trackpad 模式先 `screenPointLiesOutsideImageBoundary(x, y)`，
  命中即 `return`（事件直接消失），再 `moveCursorToScreenPoint(x, y)`
- 边界用的是 `RenderData.screenWidth/Height`，只由 `LorieView.updateInputTransform()`
  回调 `inputTransformChanged(p.x, p.y, matrix)` 填入；而 `updateInputTransform()` 只在
  `applyViewportAfterSettle()` 里被调用，那条路径要求 `surfaceReady && windowVisible &&
  isAttachedToWindow()` —— runtime/headless 面永远不满足

所以 `screenWidth = screenHeight = 0` ⇒ 任何 tap 的映射点都 > 0 + EPSILON ⇒ 判定"在画面外"
⇒ 点击消失。trackpad 模式不经过这条判断，于是表现为"默认 trackpad 能用、换到 2 点不动"。

修法（Lorie）：

1. `getInputTransform()`：几何缺失时按整面一比一兜底（`inputViewport=(0,0,surface)`，
   `inputSource=(0,0,p.x,p.y)`），仍缺就返回单位矩阵，避免除零。
2. `applyPreferences()`：设置变更后补一次 `updateInputTransform()`。
3. `screenPointLiesOutsideImageBoundary()`：尺寸未知时返回"不在外面"，不丢事件。
4. 默认触摸模式 `1 (trackpad) → 2 (模拟触摸)`。

实测（截屏判定，同一台机、同一会话）：

| 模式 | 操作 | 结果 |
|---|---|---|
| 2（默认，模拟触摸） | 点左上角 (40, 30) | GNOME **概览打开**（窗口缩略图 + 搜索栏）→ 点哪落哪 |
| 3（直接触摸） | 同一位置 | GNOME **概览打开** → 点哪落哪 |
| 1（trackpad，旧默认） | 同一位置 | 无反应（点击落在光标处，光标不在角落）——这是 trackpad 的正常语义，不是 bug |

## 4 · A6：一次会话的 trap 日志（FACT）

```
$ ls /tmp/.nr-sigsys | head -6
151-2  152-2  262-2  264-2  441-2  444-2

$ wc -l /tmp/nr-sigsys.log
246 /tmp/nr-sigsys.log
```

每个 `(nr, mode)` 在整个会话里只留一条：标记文件用 `O_CREAT|O_EXCL` 抢占，抢不到就不写。
2.0 的 `HuskRuntime.prepare()` 每个会话开始前删掉旧日志与标记目录，保证"一次会话 ↔ 一份日志"。
修复前：单会话 4499 行 / 142 KB，历史累计 5001 行。
