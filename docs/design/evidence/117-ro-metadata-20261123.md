# evidence 117 — 只读挂载也拒绝元数据写入（chmod/chown/utimensat/setxattr）

设备 RMX3357 / Android 13 / kernel 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。
脚本：`tools/device-tests/05-mount-audit.sh`（现 18 项，全通过）。

## 1. 缺口

evidence 113 修好了只读挂载的**数据**写入（`open(O_WRONLY)`、`mkdir`、`unlink`、`rename`…），
但它自己的"已知限制"里留了一条：chmod / chown / utimensat 这类**元数据**写入没有拦。
复核成立：这些调用走 `target_fd()` 钉住 inode，然后 `fchmodat`/`fchownat`/`utimensat`
作用在 `/proc/self/fd/N` 上，根本不经过 `open()`，所以只读语义漏了。

在 `chmod`/`chown`/`touch`/`setfattr` 眼里，一个 `ro` 的 bind 挂载和可写目录没有区别 ——
这会把宿主的树改掉，正是只读挂载要防的事。

## 2. 改法

新增 `ro_refuse_at(dirfd, path)`：把调用者的 `(dirfd, path)` 解析成 guest 路径
（绝对走 `abs_guest`，相对走 `resolve_dirfd_rel`，和 `openat` 同一套），再过 `ro_gp()`
（含最多 4 跳 `mnt_unmap` 链），命中只读就 `set_errno(30)`。

接在 6 个写入口上：`chmod`/`fchmodat`（`chmod_target`）、`chown`/`lchown`/`fchownat`
（`chown_target`）、`utimensat`/`utimes`/`lutimes`（`utimens_target`）、`setxattr`、
`lsetxattr`、`removexattr`、`lremovexattr`。

顺序上放在 fake-root 的 no-op 之前：假 root 下 `chown`/`utimensat` 原本直接返回 0，
在一个只读挂载上"报告成功但其实没做"同样是假话，现在明确 `EROFS`。

`mknod`/`mknodat`/`creat` 无需改：前者走 `pathop()`（113 已加只读判定），后者走 `open()`。
