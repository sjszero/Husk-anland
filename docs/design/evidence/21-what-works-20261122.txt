So: the Android kernel itself, an unmodified Ubuntu 24.04 userland, bash, coreutils,
a real gcc and make, pipes, subprocesses and a guest cwd - all inside an ordinary app
process, with no root, no namespace, no ptrace, no VM. That is the runtime, working.

WHAT IS USABLE NOW (FACT, all measured)
  * bash + coreutils, 31/31 functional checks (evidence/14, 17)
  * gcc 13.3 -> cc1 -> as -> collect2 -> ld.bfd, and make -j4 / incremental / clean
    (evidence/16, 17), with zero seccomp traps in the whole build
  * real package-shaped workloads: file tree work, symlinks, globs, pipes, redirections
  * path containment: 11 escape attempts, 0 escapes (evidence/18)
  * cost: stat one component 4.3-5.4us, four components 11-12us, fork+execve+wait 2.5ms,
    bare syscall 196ns - i.e. nothing is trapped or forwarded (evidence/18)

WHAT IS NOT THERE YET (UNKNOWN or plainly absent - do not promise these)
  * no GUI: X11/Wayland/GL/GPU, audio, camera, input. Hardware access is an SELinux
    domain question; this runtime neither provides nor blocks it (plan §4).
  * no product shell: today a probe APK starts the loader with an intent. There is no
    session/PTY/UI layer, no app-facing API, no LinuxHub 2.0 integration yet (plan §6.6).
  * no python3/getconf in this rootfs: 247 binaries, minimal Ubuntu. That is a packaging
    choice (provision more debs), not a runtime limit - gcc/make were provisioned the
    same way (tools/device-tests/provision-toolchain.sh).
  * execl/execle/execlp are not interposed (evidence/18): C programs must use execve(2),
    execv(3) or posix_spawn(3). Shells, make, gcc and python all do.
  * posix_spawn is fork-based, so a multithreaded caller pays a page-table copy
    (evidence/16). Single-threaded tools are fine.
  * 16K-page kernels untested; everything here assumes 4K (PLE110).
  * long-running daemons / systemd-style boots untested; this is a userland runner today.

Language mix of the runtime itself (see docs/design/README.md):
  Rust 3145 lines (path-shim, runtime-core, capability-probe), assembly 271 lines
  (entry_stub.S, init-hook.S), Python 630 lines (the three loader build tools),
  C 103 lines (the benchmark), shell ~600 lines (tests + toolchain provisioner),
  Java 96 lines (the probe APK), plus two patched glibc binaries that we do not
  recompile: ld.so (one extra PT_LOAD + two nop'd call sites) and libc.so.6 (two nop'd
  call sites).
