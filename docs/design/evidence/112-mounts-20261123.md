# evidence 112 — 挂载表：bind / tmpfs / 只读 bind 在无 CAP_SYS_ADMIN 下的等价物

设备 RMX3357 / Android 13 / 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。

## 1. 做了什么

`mount(2)`/`umount2(2)` 被接入 shim：
- `openat` 之前按最长前缀应用挂载表（`abs_guest`）；
- `/proc/mounts`、`/proc/self/mountinfo` 追加条目；
- 只读挂载在 `openat`（写标志）与所有改树操作上返回 `EROFS`。

表存在 `/run/husk/mounts`，每个进程首次解析路径时加载，`mount/umount` 时同步落盘。
为了让 libc 内部与 `dlsym` 路径也走我们的实现，`mount`/`umount2` 同时进了
`boot.rs BODY_PATCH` 与 `tools/loader/libc-interpose.txt`（65 of 76 slots）。

## 2. 原始输出（FACT）

```
=== bind ===
rc=0
hello                       # cat /mnt/data/file.txt，源是 /tmp/src/file.txt
=== tmpfs (write from a child) ===
rc=0
wrc=0
ramfile                     # 子进程写入并读回
=== ro bind ===
rc=0
hello
dash: 1: cannot create /mnt/ro/y: Read-only file system
ro write rc=2
file.txt                    # 源目录没有被写入
=== mounts ===
none /mnt/ro none ro,relatime 0 0
none /mnt/data none rw,relatime 0 0
tmpfs /mnt/ram tmpfs rw,relatime 0 0
=== umount ===
rc=0
rc=0
none /mnt/ro none ro,relatime 0 0
```

`findmnt` 同样列出三条（`/mnt/data`、`/mnt/ram`、`/mnt/ro`）。

`umount2` 通过 `dlsym("libc.so.6","umount2")` 直接调用也返回 0（libc 槽位重定向生效）。

## 3. 踩到并修掉的两个实现错误

1. 目标路径用 guest 路径直接打裸 `syscall`，内核按宿主根解析 → `ENOENT`。
   改成先用 `resolve_parent_follow` + `real_path` 翻译。
2. 只读检查放在映射**之后**，此时挂载点已被替换成源路径，检查永远不触发
   （`echo nope > /mnt/ro/y` 会真的写进源）。改成对调用者写的原始路径检查。

## 4. 已知限制（与 mount.md 一致）

- 挂载发生前已启动的进程看不到新挂载（容器里是全局的）；它 exec 的子进程能看到。
- 最多 8 个挂载点、路径 ≤128 字节；tmpfs 的 `size=` 不执行；只读检查暂不覆盖 `chmod/chown/utimensat`。
