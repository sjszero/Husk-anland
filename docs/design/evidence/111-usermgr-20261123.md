# evidence 111 — 账号管理：shaodw 的锁用不了，改成自己的实现

设备 RMX3357 / Android 13 / 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。

## 1. 为什么非改不可（FACT，原始输出）

```
$ useradd -m -s /bin/bash husktest
useradd: /etc/passwd.21848: lock file already used (nlink: 1)
useradd: cannot lock /etc/passwd; try again later.

$ groupadd -r huskgrp
groupadd: /etc/group.21946: lock file already used (nlink: 1)

$ adduser --system --group --home /nonexistent --shell /usr/sbin/nologin --gecos "Husk Test" husktest2
info: Adding system user `husktest2' (UID 100) ...
info: Adding new group `husktest2' (GID -1) ...
groupadd: invalid group ID '-1'
fatal: `/sbin/groupadd -g -1 husktest2' returned error code 3. Exiting.

$ ln .t1 .t2            # toybox, 没有 shim 参与
ln: cannot create hard link from '.t1' to '.t2': Permission denied
```

根因：`lckpwdf()` 用硬链接 + `st_nlink == 2` 判断锁，本域内核对 `link(2)` 返回 `EACCES`，
所以锁永远"被占用"。这不是路径改写的 bug。

## 2. 顺带发现的两个 shim 缺陷（FACT）

`getgrgid()` 对**任何** gid 都回答 `husk<gid>`，于是 `adduser` 扫 100..999 找空闲 gid 时
全部"已被占用"，返回 -1：

```
$ perl -e 'for my $g (108,555,999,4242){ my @x=getgrgid($g); print "$g => ",(defined $x[0]?$x[0]:"undef"),"\n"}'
108 => husk108
555 => husk555
999 => husk999
4242 => husk4242
```

`getgrnam()` 丢成员列表，但遍历接口是好的：

```
$ grep '^hg2:' /etc/group
hg2:x:108:hu2
$ python3 -c "import grp; print(grp.getgrnam('hg2').gr_mem)"
[]
$ getent group hg2
hg2:x:108:            # 成员不见了
$ getent group | grep hg2
hg2:x:108:hu2         # 遍历是对的
$ python3 -c "import grp; print([(x.gr_name,x.gr_mem) for x in grp.getgrall() if x.gr_name=='hg2'])"
[('hg2', ['hu2'])]
```

两处都已修：
- 合成组名只在"进程真的持有这个 gid"时才给（`process_has_gid()`：`getgroups(2)` 原始结果 + 真实 gid/egid，
  fake root 下不能用 `getgid()`）；
- `fill_group()` 把第 4 字段解析成 `gr_mem` 指针数组写进 `dst`。

## 3. 新工具（Rust，`runtime/crates/usermgr`）

一个二进制 `husk-usermgr`，按子命令分派：`useradd groupadd usermod userdel groupdel chpasswd passwd chfn chsh`。
统一在 `/etc/.pwd.lock` 上 `flock(2)`，四份库文件原子写（临时文件 + rename），默认值读 `/etc/login.defs`，
密码哈希走系统 `crypt(3)`（dlopen `libcrypt.so.1`）。

安装用 `dpkg-divert`（原文件改名 `.distrib` 并被记录），替换成两行 wrapper：

```
$ ls -l /usr/sbin/useradd && cat /usr/sbin/useradd
-rwxr-xr-x 1 u0_a302 u0_a302 51 ... /usr/sbin/useradd
#!/bin/sh
exec /usr/sbin/husk-usermgr useradd "$@"
```

为什么不用符号链接（FACT）：运行时重新进入 loader 时用的是**解析后的真实路径**，符号链接会让进程看到
`argv[0]==.../husk-usermgr`，丢掉"被当成哪个工具调用"的信息。这也是 `ls` 报错时打印完整宿主路径的原因，
记在 STATUS 的已知问题里。

`chfn` 是为了 Debian 的 `adduser`：它在 `--gecos` 时会 exec `/bin/chfn`，而真 chfn 走 PAM，
在本域里直接 "PAM: System error"，于是 adduser rc=82、账号却已经建了一半。

## 5. 仍然不行的

- `su` / 真正切换用户：没有 `CAP_SETUID`，属平台边界（容器里非特权用户同理），不是本工具的问题。
- 硬链接语义：内核对 app 私有目录拒 `link(2)`，`ln` 依旧不可用；`shadow` 那套锁协议因此永久不可用。
