# evidence 114 — POSIX 消息队列在 guest 里真正可用

设备 RMX3357 / Android 13 / kernel 4.19.191 / 4 KiB / `untrusted_app`。2026-11-23。
回归脚本：`tools/device-tests/06-posix-mqueue.py`（12 项）。

## 1. 根因（FACT）

arm64 glibc 2.39 的 `mq_*` 是 legacy 系统调用实现，`mq_unlink` 反汇编：

```
91910 <mq_unlink>:
  91918: ldrb w1, [x0]
  9191c: cmp  w1, #0x2f
  91920: b.ne 0x91968
  91928: mov  x8, #0xb5          ; __NR_mq_unlink = 181
  9192c: svc  #0
91944: adrp x0, 0x1af000        ; errno 路径
```

`__NR_mq_unlink` 在内核里没实现 → 固定 `ENOSYS`(38)。实测就是这个值：
`mq_unlink -> -1 errno 38 ENOSYS`，队列目录原样还在。所以这不是我们的 bug，
是这条 ABI 在 arm64 上本来就空着。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `runtime/crates/path-shim/src/boot.rs` | `BODY_PATCH` 64 → 75 项，补 11 个 `mq_*` |
| `tools/loader/libc-interpose.txt` | 79 → 87 项，同一个清单 |
| `runtime/crates/path-shim/src/lib.rs` | `mq_open/__mq_open_2/mq_close/mq_unlink/mq_send/mq_timedsend/mq_receive/mq_timedreceive/mq_getattr/mq_setattr/mq_notify` |
| `runtime/crates/nr-tools/src/libc_slots.rs` | 重定位器：够不着的 `b.cond`/`cbz`/`tbz` 展开成"反条件跳过 + 全宽 `b`"；stub 页改变长紧凑排布 |

上机修掉的三个 bug：

1. `mq_open` 建目录用调用方给的 `0666` → 目录无 x 位，自己都进不去（`EACCES`）。改 `|0700`，
   并对已存在的旧目录在 fd 上补 `fchmod`。**raw `fchmodat` 无效**（绕过路径改写，打到宿主路径）。
2. 目录 fd 的 `getdents64` 偏移：第二次 `mq_receive` 误判空队列 → `EAGAIN`。扫描前 `lseek(fd,0,SEEK_SET)`。
3. 成功路径污染 errno（`mkdirat` 的 `EEXIST` 留下 17）。成功时复原入口 errno。

## 3. 实测

构建与部署：

```sh
NDK=<ndk>/toolchains/llvm/prebuilt/darwin-x86_64/bin OUT=/tmp/huskloader \
  sh tools/loader/build-embedded-loader.sh
adb push /tmp/huskloader/libld.so /data/local/tmp/libld.new
# 杀掉仍映射旧 loader 的进程后 cp 到 files/libld39.so
./runtime/target/release/nr-tools libc-interpose \
  /tmp/libc.orig.so.6 /tmp/libc.slots4.so.6 tools/loader/libc-interpose.txt
# slots4 的 sha256 = 2eee99309b26e34a7a22b7bcc48dd233058e4327c0d58b9bad777198e81909fb
```
