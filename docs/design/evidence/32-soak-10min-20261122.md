# evidence 32 — goal A1 验收：`bash -i` 连续 10 分钟不死

设备：RMX3357 / MT6939…MT6893 / Android 13 / kernel 4.19.191 / 4 KiB 页
上下文：**guest**（glibc，`untrusted_app`，uid u0_a302），经 `app-rs` 里的 PTY + 我们的 loader 启动
时间：2026-11-22 21:47:26 – 21:57:26（CST），**整 600 秒**

## 脚本（设备上：`files/rootfs/tmp/soak2.sh`）

每秒一轮：20 次 `fork+exec`（`/bin/true`）+ 一行追加写；每 30 轮 `sync` 一次
（f2fs 在 panic 后回档，见 evidence 31 §6，所以必须 sync）。

## 结果（FACT）

| 项 | 值 |
|---|---|
| 墙钟 | 600 s（`while now < start+600`，时间界，不是次数界） |
| tick | 568（每次迭代含 20 次 fork/exec + 写一行 + sleep 1，所以每轮略大于 1 s） |
| fork/exec 总数 | 568 × 20 = **11 360** |
| 结束方式 | 正常打印 `SOAK-DONE ticks=568`，回到提示符 `husk@husk:/$` |
| 会话首进程 | pid **15611**，从开始到结束**同一个 pid**（没有重启、没有重连） |
| 僵尸（本 uid） | **0** |
| `session:` 日志 | 只有开头一条 `running pid=15611`，期间没有 exited/teardown |

## 期间发生的额外压力（都是真实的，不是构造的）

1. **旋转**：`cmd window user-rotation lock 1` → 窗口 1080x2400 → **2280x1080** → 回 1080x2400；
   会话 pid 不变，soak 继续跑（同时验证了 lifecycle C1）。
2. **重 I/O**：同一时间段推了 776 MB 的 rootfs 包进 `/data/local/tmp` 并解出 1.9 GB
   `files/rootfs-full`，soak 没有因此中断或丢 tick。

## 与目标的关系

goal A1 的验收句是"untrusted_app 域里 guest bash -i 连续交互 10 分钟不死，且日志里能看到
被仿真成 ENOSYS 的具体 syscall 号"。前半句 = 本文；后半句见 `files/sigsys.log`：

```
nr-init|sigsys handler installed
nr-init|sigaction|ret=0
```

与 evidence 25 / STATUS 附录里的 `nr=151/152 (setfsgid/setfsuid -> ENOSYS)` 一致。

## 复现

    adb push soak2.sh /data/local/tmp/
    adb shell 'run-as com.linuxhub.husk sh -c "cp /data/local/tmp/soak2.sh files/rootfs/tmp/; chmod 755 files/rootfs/tmp/soak2.sh"'
    # 在 app 的会话里输入： sh /tmp/soak2.sh
    # 10 分钟后： files/rootfs/tmp/soak2.log 末行 = SOAK-DONE ticks=N
